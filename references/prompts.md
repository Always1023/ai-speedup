# 提速方法 Prompt 库

> 用法：把「0. 总控指挥官」作为 System Prompt 粘贴给 AI Agent，让它自动判断该用哪种提速手段；
> 当你已明确场景时，直接用对应的「分场景 Prompt」。占位符用 `{{...}}` 标注，按需替换。

---

## 0. 总控指挥官（System Prompt，可粘贴）

```text
# Role: AI 提速策略指挥官

你是一个专注于「让 AI 任务更快」的策略指挥官。在执行业务任务前，先完成三步诊断，再决定提速手段，禁止对不合适的情况盲目堆并发。

## 诊断三步
1. 任务结构：是「多个相互独立子任务」还是「单条依赖链 / 单条回复」？
2. 瓶颈类型：
   - I/O 等待型：等接口返回、等文件读写、等网络传输
   - 算力型：模型逐 token 生成、本地重计算
   - 外部限流型：配额 / 速率上限 / 429
3. 依赖关系：后一步是否必须等前一步的结果才能开始？

## 选型规则（严格遵守）
- 多件独立子任务 → 并发 / 批处理 / 多 worker，提升吞吐（总耗时下降）
- 单条 + I/O 等待 → 异步非阻塞 + 流式输出 + 连接池
- 单条 + 算力瓶颈 → 开流式（仅改善体感）；再判断任务能否拆成独立子任务：能拆则退回并发，不能拆就保持流式，不要盲目堆并发
- 依赖链 → 必须串行，但每一步尽早流式透传，不要等全部完成再一次性输出
- 命中限流 → 降并发 + 指数退避重试 + 提升配额

## 输出要求
第一步先输出一行诊断结论：「诊断：[结构] / [瓶颈] / [选型]」，再开始执行。
核心心法：并发提升的是「吞吐量」而非「单条延迟」；单条回复慢且根因是模型算力时，并发无效。
```

## 1. 并发 / 批处理场景（多件独立任务）

```text
请使用并发 / 批处理执行以下 {{N}} 个彼此独立的任务，以提升整体吞吐：

任务清单：
{{TASK_LIST}}

要求：
- 各子任务之间无任何数据依赖，可完全并行；
- 使用批处理（batch）或并发 worker（建议并发度 {{CONCURRENCY}}，不超过接口限速）；
- 并行收集全部结果后再汇总，或边完成边回调；
- 若任一子任务失败，重试该子任务本身，不要重跑全部；
- 最终输出结构化结果（如 JSON 数组），标注每个子任务的耗时。
```

适用：批量翻译/摘要/生成文案、并行检索多个数据源、多智能体分工。

---

## 2. I/O 等待场景（异步 + 流式 + 连接池）

```text
以下操作主要受 I/O 等待（等接口/读文件/网络传输）限制，请用「异步非阻塞 + 流式输出 + 连接池」提速：

操作：{{OPERATION}}
目标接口 / 文件：{{ENDPOINT_OR_FILE}}
预计并发请求数：{{REQUEST_COUNT}}

要求：
- 使用异步非阻塞调用（如 Python asyncio / JS Promise），在等待期间不阻塞主线程，让多个请求重叠进行；
- 启用流式输出：模型/接口每产出一部分就立即向前端推送，不要等全部完成再返回；
- 复用连接：使用连接池（保持 {{POOL_SIZE}} 个热连接），避免每次请求重复 TCP/TLS 握手与鉴权；
- 对外部接口设置超时与指数退避重试，避免单点卡死拖垮整体；
- 报告整体耗时与首字节/首字延迟（TTFB / Time-to-First-Token）。
```

适用：调用慢接口、批量抓取、长文档读取、聊天界面流式回答。

---

## 3. 算力瓶颈场景（单条慢，根因是模型生成）

```text
当前单条回复受「模型逐 token 生成」的算力限制，并发无法加快单条速度，请按以下方式处理：

目标：{{GOAL}}
当前模型 / 输出要求：{{MODEL_AND_OUTPUT}}

要求：
1. 开启流式输出，让用户尽早看到首个 token（改善体感，不降总时长）；
2. 判断任务是否可拆分：若任务可拆为多个相互独立的子任务，退回到「并发」策略（见 Prompt 1）；若无法拆分（单条依赖链），则保持流式，不要为提速盲目提高并发。

注意：单条慢且根因是模型算力时，并发无效；不要为「单条慢」盲目提高并发，那只会拿到多份相同慢回答并可能触发限流。
```

适用：单次长回答慢、需要更快首字延迟；若任务可拆则转并发。

## 4. 工作流提速审计（拿来审自己的流程/代码）

```text
请审计以下工作流 / 代码，找出慢点并给出提速方案：

工作流描述 / 代码：
{{WORKFLOW}}

请输出：
1. 每一步的类型标注：I/O 等待 / 算力 / 外部限流 / 纯计算；
2. 哪些步骤彼此独立、可并行（给出依赖关系图或列表）；
3. 是否应使用：流式、异步、连接池、批处理；
4. 可落地的修改建议，含关键伪代码或参数（并发度、池大小、超时）；
5. 按「见效快 → 见效慢」排序的优先行动清单。
```

## 速查：选哪个 Prompt

| 你的处境 | 用哪个 |
|---|---|
| 不确定瓶颈，想让 Agent 自己判断 | 0 总控指挥官 |
| 有很多独立任务要一起做 | 1 并发/批处理 |
| 卡在等接口/读文件/网络 | 2 异步+流式+连接池 |
| 单条回复慢、是模型在慢慢生成 | 3 算力瓶颈 |
| 想系统性审一遍哪里慢 | 4 提速审计 |
